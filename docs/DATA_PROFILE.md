| Size | ~1.3M transactions |
| Entities | 1,000 customers, 800 merchants |
| Period | Jan 2019 – Dec 2020 |
| Columns | 23 |

**Do not commit the CSV.** `data/` is gitignored. Download it on Kaggle (Add Input
→ Datasets) or locally via the Kaggle API.

### Why this dataset

It does four jobs at once — calibration source, external reality anchor, C2ST
reference, and TSTR test set. It carries entity ids **and** timestamps, which is
what behavioural fidelity measurement requires and what most public fraud datasets
lack. And CC0 removes the licence exposure that ruled out BAF. See
[RESEARCH.md](RESEARCH.md) §1.

### Columns we use

| Column | Maps to |
|---|---|
| `trans_date_trans_time` | `Transaction.timestamp` |
| `cc_num` | customer identity |
| `merchant` | `Transaction.merchant_id` |
| `category` | merchant category → MCC mapping |
| `amt` | `Transaction.amount` |
| `lat`, `long` | customer home location |
| `merch_lat`, `merch_long` | merchant location |
| `city_pop` | population context |
| `is_fraud` | hidden evaluation label |

Column names differ from ours. Keep **one** explicit mapping module
(`evaluation/anchor_map.py`), not renames scattered through the codebase.

## 4. Notes and caveats

Record here anything surprising, and anything the simulator deliberately does
**not** copy.

- Sparkov is itself **synthetic** — rule-generated, not real transactions. It is a
  reasonable behavioural reference, not ground truth. Say so in the report; a
  reviewer who knows the dataset will otherwise say it for you.
- No device or IP columns. Device-level structure is a modelling assumption.
- Two-year span with only 1,000 customers means per-customer history is long. Our
  simulator's shorter window will differ in account age — note the effect.
